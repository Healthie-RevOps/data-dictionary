# Data Dictionary — Proposed Fills for Blank Cells

Generated by cross-referencing each documented field against live Salesforce metadata (`FieldDefinition` via the Tooling API, queried 2026-05-07 against bill.coffin@gethealthie.com). For every row in the dictionary that has a blank `Source / Update`, `Owner`, `Sensitivity`, `Description`, or `Dependencies / Notes` cell, this document proposes a fill grounded in either the field's SFDC `Description` (when set in field setup) or a heuristic derived from data type, label, and naming conventions.

## How to read this
- **API name** — the SFDC `QualifiedApiName` matched by label. Use this to verify the row maps to the correct field.
- **Source / Update**, **Owner**, **Sensitivity** — heuristic fills based on field metadata; review against your actual workflows.
- **Description** — when SFDC has a Description set in field setup, that text is used verbatim. Otherwise a typed placeholder is shown; treat those as a starting point only.
- **Dependencies / Notes** — left as `—` when no signal could be derived; fill these in manually as you have business context.
- Sensitivity classes used: PII / Financial / Financial ID / Internal (per dictionary methodology).

## Discrepancies / Anomalies
- **Account → "Product Health Score"** — no matching field found in SFDC. Verify field exists or update label.

## Appendix: Data Quality Findings

Items surfaced during this audit that may warrant a dictionary update or SFDC change:

1. **Account "Product Health Score"** is documented but no field of that exact label exists. Closest matches: `Health_Score__c` (Picklist), `Product_Health_Breakdown__c` (Formula Text), `Product_Health_Label__c` (Formula Text). Recommend renaming the dictionary entry to whichever is canonical.
2. **Account.`Active_Stripe_Subscriptions__c`** and **Account.`Stripe_Subscription_Canceling__c`** appear in the FieldDefinition metadata but are not readable to standard users (FLS-restricted). Verify whether these should be exposed for reporting; at minimum, document the FLS restriction in the dictionary.
3. **`Stripe_Subscription__c.Enterprise_Plan_Start_Date__c`** is null for Daylight Health (cus_NimGpmgqnBcHoZ) — the Enterprise plan started 2024-01-01 (per `Stripe_Created__c` on the Enterprise-group line item) but the dedicated Enterprise plan start field isn't backfilled. Same likely applies to `Plus_Plan_Start_Date__c`, `Group_Plan_Start_Date__c`, etc. on other accounts. Recommend a Salesforce Flow / scheduled job to populate these from line-item creation dates.
4. **No SFDC field tracks the Stripe Connect (`acct_*`) account** for a customer. If support/finance workflows need this, add a field on `Stripe_Customer__c` or `Healthie_Organization__c`.
5. **`Account.Subscription_Type__c`** appears alongside the more reliable `Current_Plan__c` (Stripe-synced) and `Stripe Subscription.Plan_Group__c`. Decide which is canonical and either deprecate or document the difference. The Daylight Health record had `Subscription_Type__c = null`.
6. **Inline help text was not pulled** for this audit (the Tooling API requires per-field queries for `CustomField.Metadata`). Many descriptions in this output are heuristic; for the highest-value fields (formulas like `ARR__c`, `Product_Health_Score`-equivalent, `Account_Tier__c`), pulling the formula body would strengthen the description. The example pulled earlier showed `Account_Tier__c` formula resolves to `Strategic` (>$200K ARR) / `Growth` (>$50K) / `Foundational` (else).
7. **Typo in SFDC field API name**: `Vitally_Onboarding_Health_Scofre__c` (note "Scofre" instead of "Score"). The label reads correctly as "Vitally Onboarding Health Score". Renaming the API name would break every formula, report, and integration that references it, so it should likely stay as-is — but flag in the dictionary so anyone writing SOQL knows.
8. **SFDC `Description` coverage is sparse**: only ~15% of fields across the 7 objects have any value in `FieldDefinition.Description`. Best coverage is on TaskRay (47%, managed package) and Account (21%); worst is Stripe Subscription (2%) and Healthie Organization (5%). Filling these in inside SFDC field setup would let any future re-audit pull richer descriptions automatically rather than relying on heuristics.
